# Placeholder assets

Every visual of the mod is temporary. The mod ships **no texture, no model
and no icon of its own** except the two programmer-art sprites of the
reloading press. Everything else a player sees is a vanilla asset borrowed
until final art exists.

This is the one list of them. The tables are generated
(`tests/write_recipes.lua`) from where each placeholder is configured, and
the suite fails when the document and the configuration disagree.

Marker in code and scripts: `PLACEHOLDER_VISUAL`.

## Replacing a placeholder

The workflow is meant to be: **change one value, run the tests, done.** No
gameplay code names a sprite, an icon or a model.

| What | Change | Then |
|---|---|---|
| A sprite or window icon that Lua names | the entry's `value` in `AC_Visuals.LIST` (and, where the row says it mirrors a script, the same name in that script) | `lua5.1 tests/write_recipes.lua`, then the suite |
| An item's inventory icon | `Icon = ...` of the item in `AC_Items.txt`; ship the PNG as `media/textures/Item_<name>.png` | the same |
| An item's world model | `WorldStaticModel = ...` of the item; ship the model script and its mesh and texture | the same |
| A spent case's look | nothing by hand: a spent case copies its unused case. To give spent cases a look of their own, set `Icon` / `WorldStaticModel` in `AC_SpentCases.buildItems` | the same |
| The reloading press's sprites | replace `art/reloading_press/src/ammomaking_press_01_0.png` and `_1.png`; `python tools/build_tiles.py art/reloading_press/tiles.json` | the suite; the sprite names do not change |

What the tests check for every row: the borrowed icon and model still
exist in the installed game (`tests/engine_snapshot.lua`, refreshed by
`tools/pz_compat.py --update`), and the game-start check reports a sprite
that no tile definition has.

What final art is wanted for each is specified in `docs/ART_HANDOFF.md`.

## Notes

- **Vanilla assets are referenced, never copied or changed.** An item
  script names a vanilla icon or model; nothing of vanilla's is in the
  repository or the release.
- **The analyzer's sprite is not claimed as an entity.** It is drawn by an
  `IsoThumpable` the mod creates, so no other mod's entity can collide with
  it. If a game update turns that tile into a moveable or lets an entity
  claim it, `tools/pz_compat.py` says so.
- **The press's sprites are the add-on's own names.** A vanilla sprite
  cannot be borrowed for a station: a sprite claimed by two entity scripts
  stops every world from loading (`docs/RELOADING_PRESS_DESIGN.md` 2.4).
- Five items of the geology stage have no world model of their own; what
  the game draws for them on the ground is the engine's default.
- Whether a borrowed model looks right at the size of the item it stands
  for is **REQUIRES FUTURE IN-GAME VERIFICATION**, like every visual.
